# 实践手册：我怎么用这个仓库

> 前面几篇是地图和重构。这篇是具体行动——知道了这些，我下一步做什么？

## 快速上手（30 秒安装）

```bash
npx skills@latest add mattpocock/skills
```

选你想要的技能，**确保选了 `/setup-matt-pocock-skills`**。

然后在 agent 中跑 `/setup-matt-pocock-skills`，它会逐个问你：
1. 用哪个 issue tracker（GitHub / GitLab / local / other）
2. triage 标签怎么映射
3. 单上下文还是多上下文

跑完就可以用其他工程技能了。

## 不知道用什么技能？

跑 `/ask-matt`，它会问你当前的情况，然后推荐合适的流程。

这个技能是整个仓库的**路由器**——你只需要记住一个技能，其他技能它帮你记。

## 日常使用场景

### 场景一：我要加一个新功能

1. `/grill-with-docs` — 和 agent 对齐想法，建立共享术语，记录到 CONTEXT.md
2. `/to-spec` — 合成 spec（不重新提问）
3. `/to-tickets` — 拆成 tracer-bullet 工单
4. 依次对每个工单跑 `/implement`
5. 每个 `/implement` 内部：/tdd 驱动 → 完成 → /code-review

**不要跳步骤**。特别不要跳过 `/grill-with-docs`——对齐失败是这个系统里成本最高的失败。

### 场景二：别人的仓库进来一个 issue

1. `/triage` — 说"看看有什么需要处理的"
2. 它会展示三个桶：未标标签的 / needs-triage / 有回复的 needs-info
3. 你挑一个，它走状态机：验证 claim → 需要时 grill → 标状态

### 场景三：有个 bug 我死活找不到原因

1. `/diagnosing-bugs` — agent 自主触发的诊断循环
2. 如果诊断发现是代码设计问题，用 `/improve-codebase-architecture` 处理根本原因

### 场景四：代码库越来越烂

1. `/improve-codebase-architecture` — 扫描深化机会
2. 选一个，用 `/codebase-design` 的词汇设计新接口
3. 走主流程实现

### 场景五：我想学 Python（或其他技能）

1. 在 workspace 里跑 `/teach`
2. 它会搭一个完整的学习工作区
3. 每节课一个 HTML 文件，有知识 + 练习 + 反馈
4. 支持跨 session 学习

## 关键的 meta 技能：怎么写自己的 skill

`/writing-great-skills` 是一份完整的指南。GLOSSARY.md 定义了所有术语。

写技能的基本流程：
1. 确定调用方式（user-invoked vs model-invoked）
2. 有没有步骤？还是有参考就够？
3. 每个步骤的完成标准是什么？
4. 有没有 leading word 可以用？
5. 检查每一行：是 no-op 吗？是 negation 吗？和别处重复吗？

## 对我（学习达人）的启示

这个 repo 本身就是一个学习材料。我把它拆了又重组，这个过程就是"我的重构"。

我接下来可以做的事：

1. **如果我要写一个自己的 skill**——用 `/writing-great-skills` 作为参考，GLOSSARY.md 里的每个条目都是可执行的规则
2. **如果我要评估一个已有的 skill**——看它的 completion criterion 是清晰还是模糊，检查有没有 no-op 行
3. **如果我想理解 Matt 的思维方式**——重点读 GLOSSARY.md。它是这个仓库方法论的压缩版
4. **如果我想在项目里引入这套系统**——先跑 setup，然后用 `/grill-with-docs` 建共享语言，这是 ROI 最高的第一步
5. **如果我只能记住一件事**——在给 agent 写指令时，每一行都要问：它改变了默认行为吗？没有就删掉。有，确保它不是 negation（禁止式指令会让禁止的行为更突出）
