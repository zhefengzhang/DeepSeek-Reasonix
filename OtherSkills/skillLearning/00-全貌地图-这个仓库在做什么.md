# 这个仓库在做什么？

> 作者：Matt Pocock（TypeScript 社区名人，Total TypeScript 作者）
> 仓库：https://github.com/mattpocock/skills

---

## 一句话说清楚

这是一个 **编码 Agent 的操作系统**——一套可组合的技能（skills）集合，让 Claude Code、Codex 等 AI coding agent 按照**可预测的工程流程**工作，而不是随缘输出。

它不是一套提示词模版，是一套**行为约束系统**。

---

## 它解决什么问题？

作者在 README 里列出了四个最常见失败模式：

| # | 失败模式 | 问题的本质 | 对应的技能 |
|---|---------|-----------|-----------|
| 1 | Agent 没做对（misalignment） | 你和 agent 之间理解不一致 | `/grill-me`, `/grill-with-docs` |
| 2 | Agent 废话太多（verbose） | Agent 不用共享术语，每次用20个词解释1个概念 | `/domain-modeling`（共享语言） |
| 3 | 代码跑不通（broken code） | 缺少反馈回路，agent 在盲飞 | `/tdd`, `/diagnosing-bugs` |
| 4 | 代码变成一坨泥巴（ball of mud） | Agent 加速了软件熵增，没人管设计 | `/improve-codebase-architecture`, `/codebase-design` |

核心洞察：**Agent 加快了编码速度，也加快了烂代码产生的速度。你需要更严格的工程纪律，而不是更少的纪律。**

---

## 这个仓库不是什么

- ❌ **不是 Prompts 合集**——每个 skill 是一份结构化的行为规范文档，不是一两句提示词
- ❌ **不是 GSD/BMAD/Spec-Kit 的替代品**——那些框架替你拥有整个流程，让你失去控制；这套技能让你保留控制，只是增加了可预测性
- ❌ **不是某个模型的专属**——README 说"work with any model"
- ❌ **不是插件/扩展**——它是一组 markdown 文件，通过 skills.sh 标准安装到 agent 的 skill 目录中

## 核心设计哲学

### 1. 可预测性（Predictability）是第一美德

技能的存在意义是在随机系统（LLM）中挤出确定性。可预测性 = agent 每次走**同样的过程**，不是每次产生同样的输出。一个头脑风暴技能应该可预测地发散，不是可预测地输出同一个点子。

### 2. 两种调用模式，两种成本

| 模式 | 谁可以调用 | 成本 | 使用场景 |
|------|-----------|------|---------|
| **User-invoked**（用户调用） | 只有你输入 `/name` | 认知成本：你要记住它存在 | 流程编排技能，需要人的判断 |
| **Model-invoked**（模型调用） | 你和 Agent 都可以 | 上下文成本：description 每轮都加载 | Agent 需要自主触发的技能 |

关键规则：**user-invoked 技能可以引用 model-invoked 技能，但不能引用另一个 user-invoked 技能**（因为 user-invoked 没有 description，Agent 发现不了它）。

### 3. 信息层级（Information Hierarchy）

技能的内容按照 agent 需要的紧迫程度分层：

```
1. Steps（步骤）—— 有序的操作，agent 按顺序执行
2. In-skill Reference（技能内参考）—— 定义、规则、事实
3. Disclosed Reference（外置参考）—— 通过上下文指针触发的文件
```

每层之间通过**上下文指针**（context pointer）连接。指针的措辞决定了 agent 何时以及多可靠地访问到材料。
